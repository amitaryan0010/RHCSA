Linux systems continuously generate logs from services, kernel events, and system activities. With systemd, these logs are centralized in the journal, making journalctl the primary tool for accessing and analyzing them. It provides structured, searchable logs with powerful filtering options, simplifying troubleshooting and system monitoring.

Understanding The Systemd Journal System
    Journalctl is the command-line tool that lets you access and filter the systemd journal – basically your system’s diary of everything that happens behind the scenes.

Configuring Persistent Journal Storage For Complete System History

By default, RHEL9 has Storage set to auto in /etc/systemd/journal.conf
    [root@rhel-9 log]# cat /etc/systemd/journald.conf | grep Storage
    #Storage=auto

    It has 3 options:
        - auto: systemd-journald service checks if /var/log/journal directory exists then it will write the logs there else, under /run/log/journal/
        - volatile: always write at /run/log/journal
        - persistent: always write at /var/log/journal (if directory doesn't exist then it will create the directory)

    If you set the Storage to persistent in live/running system then :
        - try to restart the service:
            # systemctl restart systemd-journald
        - if still it will not wrtiing, you need to flush the journal so that daemon will start wrting journal under /var/log/journal:
            # journalctl --flush
        - reboot, it will auto start writing.

    If still it is not writing, then check the permission, ownership and selinux context:
        # chown root:systemd-journal /var/log/journal
        # chmod 2755 /var/log/journal
        # semanage fcontext -a -t systemd_journal_t "/var/log/journal(/.*)?"
        # restorecon -RvF /var/log/journal
        OR
        simply run this command:
        # systemd-tmpfiles --create --prefix /var/log/journal

_______________________________________________________________________________________________________________________________________________

We can change the default parameter in /etc/systemd/journal, like:
    - Storage to auto/volatile/persistent
    - SystemMaxUse=500M (maximum disk space the journal folder can consume under /var/log/journal/. Once logs cross this cap (e.g., 500 Megabytes), journald automatically deletes the oldest logs to make room for new ones.)
    - SystemMaxFiles=100 & RuntimeMaxFiles=100 (explicitly sets a maximum limit of 100 individual journal files )
    - SystemKeepFree=1G (Ensures that journald always leaves at least 1 Gigabyte of free space on your disk partition for other system services, stopping log growth if disk space runs critically low.)
    - MaxRetentionSec=1month (Explicitly limits logs by time/age rather than size. Any log entries older than 1 month are automatically purged, naturally capping how long your boot list can grow.)

_______________________________________________________________________________________________________________________________________________
Disk and Memory Consuming Formula:
    1. The Disk Capacity Formula (The Cap)
        - 10% of the total filesystem size where the directory resides. 
        - An absolute hard ceiling of 4 Gigabytes (4G).
        
        Example: If your root / disk partition is 20 GB, the journal will cap out at 2 GB (10%). If your partition is 100 GB, it will cap out at the maximum hard limit of 4 GB.

    2. The Memory Capacity Formula (Runtime)
        - 10% of your total system RAM size.
        - An absolute hard ceiling of 400 Megabytes (400M).
